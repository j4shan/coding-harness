# instructions

Instruction documents written to be read by a coding agent — working conventions, review and
reporting formats, testing rules, authoring and terminology discipline.

One file per subject, named for the subject. A document here is a **source** to compose from: it
is copied into or referenced by a project's own `AGENTS.md`, rather than being loaded from this
repository at runtime.

Same portability bar as `skills/`. An instruction that names a particular spec file, product, or
folder layout belongs in the project that has them. Where a rule is worth generalizing, state it
against the role an artifact plays and let the consuming project supply the specifics.
